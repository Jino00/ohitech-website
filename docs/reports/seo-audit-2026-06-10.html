🔴 HIGH — 즉시 수정 (2건)

HIGH 1. 비-www 도메인 미리다이렉트 — 사이트 전체 중복 서빙

증거 curl https://ohitech.co.kr/ → 200 (리다이렉트 없음). http://ohitech.co.kr → 301 → https://ohitech.co.kr/(비-www 그대로)
영향 모든 페이지가 www / 비-www 두 호스트에서 동일하게 노출. canonical이 www를 가리켜 완화되고는 있으나, 크롤 예산 분산·신호 분산·네이버 중복문서 판정 위험.
수정 서버(nginx)에서 비-www → www 301 리다이렉트 추가:
server {
    listen 443 ssl;
    server_name ohitech.co.kr;
    # (기존 SSL 인증서 설정 재사용)
    return 301 https://www.ohitech.co.kr$request_uri;
}
확인법 curl -sI https://ohitech.co.kr/ | grep -i location → https://www.ohitech.co.kr/ 301 확인

HIGH 2. /about 영문·중문 canonical이 한국어 페이지를 가리킴 (교차 로케일 canonical)

증거 라이브 /about?lang=en의 <link rel="canonical"> = https://www.ohitech.co.kr/about (한국어). 다른 모든 페이지(홈·제품·인사이트·문의)는 self-canonical 정상.
영향 구글이 영/중 회사소개를 한국어 페이지의 중복으로 처리 → 영문·중문 /about 색인 억제. canonical과 hreflang이 충돌하면 canonical이 우선되어 hreflang 클러스터도 약화됨.
원인 src/app/about/page.tsx:56 — buildAlternates(`${baseUrl}/about`) 호출 시 locale 인자 누락 (기본값 "ko"). 다른 페이지는 buildAlternates(url, locale)로 전달.
수정 1줄:
- alternates: buildAlternates(`${baseUrl}/about`),
+ alternates: buildAlternates(`${baseUrl}/about`, locale),
확인법 배포 후 curl -s "https://www.ohitech.co.kr/about?lang=en" | grep canonical → /about?lang=en 확인
