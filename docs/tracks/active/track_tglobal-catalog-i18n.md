# 트랙: T-Global 카탈로그 다국어화 (zh + ja)

## 목표
`thermal-catalog.ts`(10 카테고리 / 67 제품)를 zh·ja로 번역해, 해당 로케일에서 영어로
떨어지던 마지막 구간을 없앤다.

## 사용자 원문 인용
> "T-Global 카탈로그도 고쳐줘" (2026-07-17)

## 배경
`track_ja-locale`의 D-11에서 codex가 지적하고 합의한 **별도 트랙 부채**를 실제로 상환하는 작업.
당시 결론: 카탈로그는 ko/en만 있어 **zh도 영어로 떨어지므로** ja만 고치면 zh가 유일하게
영어로 남는 새 불일치가 생긴다 → zh·ja를 **동시에** 해야 한다.

## 확정 결정사항

### D-1. 번역은 `.ts`가 아니라 파이프라인 레이어에 넣는다
`thermal-catalog.ts` 헤더: `AUTO-GENERATED by scripts/tglobal/build-catalog.mjs — do not edit by hand`
→ 손으로 고치면 재생성 때 소실. **파이프라인을 확장한다.**
```
data/_raw/<cat>.json            크롤링 원본(영어, 슬러그의 진실)
data/_raw/_{ko,ja,zh}/<cat>.json  로케일 레이어  ← fill-*.mjs 가 생성
        ↓ build-catalog.mjs 병합
src/app/products/data/thermal-catalog.ts  (생성물, 커밋됨)
```

### D-2. 원본 데이터는 git에 없다 — 본 저장소 로컬에만 존재
`.gitignore` 3번 줄 `data/` → `data/_raw` 21개 파일이 **커밋된 적 없음**(`git log -- data/` 0건).
워크트리에는 아예 없어서 본 저장소에서 복사해 왔다.
→ **이 데이터가 사라지면 카탈로그 재생성 불가.** 별건이지만 기록해 둔다.

### D-3. 번역 원본은 `scripts/tglobal/i18n/{ja,zh}.json` (커밋됨)
`fill-ko.mjs`는 번역 테이블을 **JS 인라인**으로 들고 있다(33KB). `scripts/`는 gitignore 대상이
아니므로 그렇게 해도 버전 관리는 된다.
→ 같은 목적을 유지하되 **JSON으로 분리**. 이유: 33KB 인라인 JS는 문구 하나 고치려면
   코드 파일을 건드려야 하고 diff가 읽히지 않는다. JSON은 번역자가 직접 편집 가능.
→ 적용기는 `fill-locale.mjs <ja|zh>` 하나로 통합 (fill-ko.mjs는 기존대로 둔다).

### D-4. 폴백은 en → ko. 절대 다른 외국어로 떨어지지 않는다
`lib/locale.ts`의 `localizedField()`와 동일 철학.
미번역 항목은 `""`로 생성되고 `pName`/`pDesc`/`pBenefits`/`catLabel`이 en → ko로 폴백.
→ 번역이 일부 빠져도 **빌드가 깨지지 않고**, ja 화면에 중국어가 새지 않는다.

### D-5. 모델명·품번·수치·규격은 번역하지 않는다
`TG-A6200`, `CMC`, `Li98`, `10^6-10^9 ohms`, `W/mK`, `UL94 V-0`, `Infineon AN2019-05` 등.
`track_ja-locale` D-4와 동일 원칙.
